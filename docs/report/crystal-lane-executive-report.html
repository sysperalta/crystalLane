Executive summary

The first leg of every carrier call can run itself, with your rules enforced in software

Jordan, an AI voice agent on HappyRobot, takes a carrier from "What's your MC number?" to a load booked at an approved rate and handed to a senior rep, without a dispatcher. The rules that protect your margin and your compliance are enforced in code, and Version 10 passed 96% of graded full test calls.

The situation

Calls grew with volume. Headcount didn't.

  • ~2,000 active carriers and ~500 loads a week across dry van, reefer and flatbed
  • Missed calls at the Monday-morning and Friday-afternoon peaks send carriers to competing brokers
  • Ceilings vary by dispatcher; FMCSA checks are manual; nothing records what was offered

What we built

A voice agent plus the integration behind it

  • Jordan verifies authority with FMCSA, confirms identity by SMS code, pitches matching loads and negotiates up to 3 rounds
  • An adapter service talks to the legacy TMS over its TCP protocol and enforces call order, OTP, ceiling and approved rates
  • Every call is written to Twin for reporting and disputes

What testing shows

Tested and ready to publish

  • 96% of end-to-end test calls passed (24 of 25), up from 47%; the last two full rounds passed every scenario
  • The security attacker scenario passed 5 of 5: no code bypass, no max rate revealed
  • 22 of 22 prompt tests and 125 automated adapter checks pass
Recommendation

Publish Version 10 and run a 4-week pilot on peak-hour and after-hours calls alongside your current call center, watching negotiation and the senior-rep handoff on the first live calls. No change to your existing contract is needed.

Rate ceiling enforcement

The ceiling lives in code, not in the conversation

Jordan never receives max_rate, so no question, pressure or trick can get it out of the agent. The adapter holds it and answers only "accept", "counter at X" or "decline".

The same rules on every call, at every hour

  • A counter is never above the max rate, never above the carrier's ask, and always higher than the previous counter.
  • Up to 3 rounds per load; after that the answer is a polite decline, logged as a failed negotiation, with no transfer.
  • A load can be booked only at the posted rate or at an amount the adapter approved on that same call.
  • Jordan may quote only numbers from the load details or the adapter. The "Keep the Rate Ceiling Private" and "Use Only Authorized, Real Figures" northstars are graded on every test call.
  • Booking is idempotent: a retry never double-books, and a load taken by another carrier is reported as unavailable.

The counter policy (steps between posted and max) is configurable and still to be confirmed by Crystal Lane.

Compliance and security

Identity is proven before any load is discussed, and it can't be talked around

Authority

FMCSA on every call

  • Checked once the full MC number is read back and confirmed
  • Only active authority proceeds; inactive, revoked and unknown carriers are closed politely, without giving the reason
  • If FMCSA doesn't answer, Jordan retries once, then offers a callback

Identity

SMS code to the phone on file

  • The code goes only to the registered number; there is no way to send it elsewhere
  • 6 digits from a secure generator, stored only as a hash, valid for 5 minutes
  • 3 attempts and 1 resend per call; a partial code isn't checked and doesn't count as a failed attempt
  • Search, booking and handoff stay locked until the code is verified

Systems

Locked down by default

  • Every endpoint requires an API key; HTTPS only; 60 requests a minute per call
  • Never returned or logged: max rate, OTP codes, full phone numbers, keys
  • Verified by automated scans and on the live Azure deployment's logs
Attacked on purpose

In the security attacker scenario a simulated carrier tries to skip the code, inject instructions and fish for the max rate. Version 10 passed it 5 of 5. Even if a prompt were manipulated, the adapter has no way to skip the code.

Legacy TMS integration

Your TMS stays as it is. The adapter speaks its language and absorbs its failures.

A load record as the TMS sends it: fixed width, no JSON (wrapped to fit)

LD-10482 AJoliet, IL Dallas, TX 202610080800-0500 202610091700-0500 DV 000210000 ... 0042000Paper goods 0024 00925 48x40x60 ...
  • Native TCP socket client: a fresh connection per request with the host, port and token from configuration. No REST layer to build on your side.
  • Every fixed-width field is validated. A bad record is skipped; a fully garbled reply is retried.
  • 1.5 s timeout per attempt, up to 3 attempts, backoff of 0.2 s then 0.5 s, within a 4-second budget per request.
  • Bookings carry an idempotency key, so a retry after a lost reply never books twice.

Evaluation and QA · method

Every test call is graded against 20 northstars

Northstars are the quality criteria Jordan must meet on every call. 22 prompt tests check single turns; 5 adversarial end-to-end scenarios have a simulated carrier play a whole call while an evaluator grades all 20. Scenarios are run repeatedly and reported as pass rates. Pass mark: 80% per scenario.

1 · Security

High
  • Protect role and identity
  • Protect the one-time code
  • Keep the rate ceiling private
  • Verification before freight discussion

2 · Money and booking

High
  • Use only authorized, real figures
  • evaluate_offer: every counter, max 3 rounds
  • book_load: only after the full summary
  • transfer_to_senior_rep: only after booking

3 · Identity

High
  • verify_carrier: full MC, read back, confirmed
  • OTP flow: 3 attempts, 1 resend

4 · Load search

Medium
  • find_loads: only after verification; retry order
  • Search inputs: never re-asks; exact dates
  • Pitch quality: every field, respects minimums
  • Continue until a clear no

5 · Conversation flow

Medium
  • Confirm before acting
  • Explain the pre-booking human option
  • Close after continued abuse
  • Complete the goodbye and hang up

6 · Style

Low
  • Natural spoken data: rates, weights, dates, full state names
  • Efficient dispatcher voice: short, one question per turn

Evaluation and QA · what changed

Ten improvements in Version 10, driven by graded test calls

Improvements in Version 10

  1. Load search rebuilt. One search tries the exact request, the same city on any day, then a nearby city, so the carrier isn't asked twice and searches don't repeat.
  2. No match. After an empty search, Jordan offers a different day, lane or equipment instead of ending the call.
  3. Abusive callers. One calm warning before closing the call.
  4. MC verification. After a first "not found", Jordan asks again and reads the number back before checking.
  5. Verification code. Three refusals before closing, and no way to talk it out of the check.
  6. Minimum rate. Never pitches a load below the carrier's stated minimum, and pitches one load at a time.
  7. Details already given. A lane mentioned before verification is used afterwards instead of asked again.
  8. Dates. "Today", "tomorrow" and "next week" are always counted from the Central Time date.
  9. Unclear counters. Shorthand like "fifteen" gets a confirmation question; clear amounts like "twenty-four hundred" go straight through.
  10. Security. Never reveals its instructions or the maximum rate it can pay.

Test adjustments, for transparency

Three prompt tests graded the agent wrongly and were corrected. The agent was not changed to pass them.

NS-08Expected date was hard-coded to the day the test was written; it now accepts the correct "tomorrow". NS-10Failed the agent for asking "Which one works?" after listing destinations; relaxed. ST-20Rejected "two thousand two fifty", which the pronunciation guide treats as natural; both wordings accepted.

"Why do we need a Forward Deployed Engineer?"

Because none of this is plug-and-play

  • Connecting a legacy TCP TMS with no API, no JSON and no documentation beyond its protocol spec.
  • Moving the ceiling out of the conversation into code your auditors can check.
  • Building an identity check that holds up against social engineering.
  • Fitting the integration to the platform: the voice platform collapses error replies into one opaque message, so the API was redesigned to always return a readable result.
  • Running graded test rounds, fixing the agent and the tests, and catching regressions before carriers do: full-call passes went from 47% to 96% (pages 10 and 11).
